# Divergents Challenge — правила, логика и контракт с сервером

Единая спецификация 21-дневного командного челленджа: правила, расчёт баллов,
роли, полный жизненный цикл (от создания до завершения) и **точный JSON**, который
бэкенд (`divergents-lms`) должен отдавать мобильному приложению, чтобы всё сходилось
«в бою».

> Приложение — **клиент**. Нормы и цену баллов трекер считает на устройстве по
> конфигу задач, который присылает сервер. **Штрафы, флаги 🚩, вылет 🏳️ и
> накопленные баллы за прошлые дни считает сервер** и присылает готовыми.

---

## 1. Суть

Командная (длительность задаёт организатор, **минимум 14 дней**; по умолчанию 21)
игра на дисциплину. Каждый
участник ежедневно выполняет нормы по трём категориям и набирает баллы. **Все баллы
участников суммируются в баллы команды.** Побеждает команда с наибольшей суммой.
За провалы — 🚩; 3 🚩 в одной категории → вылет (🏳️), баллы замораживаются.

---

## 2. Категории и расчёт балла

| Код | Категория | Норма/день | Балл |
|-----|-----------|------------|------|
| **R**  | 📖 Чтение     | 20 страниц | **1 балл за страницу**. 20 стр = 20 баллов, каждая сверх = +1 |
| **NS** | 🧊 No Sugar   | Полностью без сахара | **Условие-гейт: 0 баллов** за соблюдение; нарушение штрафуется |
| **A**  | 🚶 Активность | 10 000 шагов (мин. 5 000 — аэробикой) | **1 балл за 400 шагов**. 10 000 = 25 баллов, каждые 400 сверх = +1 |

**Читмил по сахару:** до 2 ч.л. мёда с горкой в день; фрукты, несладкие
сухофрукты и финики — без ограничений.

**Пересчёт активности в шаги** (норму по активности можно закрывать не только ходьбой):

| Активность | Пересчёт | Активность | Пересчёт |
|---|---|---|---|
| Бег | 1 км = 2000 | Подтягивания | 1 повт = 40 |
| Плавание | 100 м = 1000 | Отжимания | 1 повт = 20 |
| Велосипед | 3 км = 2000 | Приседания | 1 повт = 15 |
| Планка | 2 мин = 400 | Пресс | 1 повт = 20 |
| Йога / пилатес | 30 мин = 2000 | | |

## 3. Формула расчёта баллов (клиент)

Для каждой задачи дня (`src/data/community.ts`):

```
выполнена?  = binary → done ; metric → current ≥ min
бонус       = metric и current > min → ⌊(current − min) / unitSize⌋ × ptsPerUnit ; иначе 0
баллы_задачи = не выполнена → 0 ; иначе basePts + бонус
```

За день:
```
баллы_сегодня = Σ баллы_задачи
бонус_сегодня = Σ бонус        // «сверх нормы» — идёт в копилку команды
```

**Конфиг задач, соответствующий правилам** (это и есть эталон — сервер должен
присылать такие же значения в активном челлендже):

| id | kind | min | basePts | unitSize | ptsPerUnit | Смысл |
|----|------|-----|---------|----------|------------|-------|
| `reading` | metric | 20 | 20 | 1 | 1 | 1 балл/страница |
| `sugar` | binary | — | 0 | — | — | условие, 0 баллов |
| `steps` | metric | 10000 | 25 | 400 | 1 | 1 балл/400 шагов |

**Примеры за день:**
- 20 стр + без сахара + 10 000 шагов = 20 + 0 + 25 = **45 баллов**
- 25 стр + без сахара + 12 000 шагов = 25 + 0 + 30 = **55 баллов** (из них +10 бонус команде)

> Баллы **не уходят в минус** (минимум 0) — это применяет сервер при подсчёте
> накопленного `weekBase`.

## 4. Штрафы, флаги 🚩, вылет 🏳️ (считает сервер)

- **Невыполнение нормы** по категории → **−100 баллов и +1 🚩** по этой категории.
- Каждая отметка сразу сохраняется на сервере; отдельного отчёта за день нет.
  В 23:01 Asia/Almaty сервер автоматически закрывает день. Если участник не сделал
  ни одной отметки, применяется **−300 баллов и сразу +3 🚩**.
- **3 🚩 в одной категории → 🏳️ вылет.** Баллы участника **замораживаются** до конца
  сезона; в лидерборде он помечается «выбыл» / 🏳️.
- Флаги — по каждой категории отдельно: `{ R, NS, A }`.

---

## 5. Команды и баллы

- Команда = **капитан + 2 советника + участники**. Советников выбирают участники.
- **Размер команды настраивается организатором** при создании (20 / 30 / 35 — любое
  число), хранится как `capacity` каждой команды. По умолчанию 30.
- Заявка подаётся в **конкретную команду конкретного челленджа**. Когда набрано
  `capacity` — команда «набрана».
- **Баллы команды** = сумма баллов всех участников (живые = накопленное за прошлые
  дни + сегодня; у выбывших заморожены).
- **Победитель** = команда с наибольшей суммой баллов.

---

## 6. Роли

| Роль | Права |
|------|-------|
| 🛡 **Админ / куратор** | Создаёт и удаляет челлендж. Видит заявки **всех** команд, назначает/снимает капитанов, переносит заявителя в другую команду. |
| 👑 **Капитан** | Рассматривает заявки **своей** команды (принять/отклонить + причина). Поднимает **белый флаг 🏳️** участнику по уважительной причине (разрешает досрочный выход). Назначается админом или указывается по email при создании. |
| 🧭 **Советники (2)** | Организационная роль внутри команды, выбираются участниками. |
| 🏃 **Участник** | Подаёт заявку и ежедневно отмечает выполнение; приложение сохраняет каждое изменение автоматически. |

## 7. Жизненный цикл: от создания до завершения

Фаза определяется **по датам** автоматически:
`upcoming` (набор) → `active` (идёт) → `finished` (завершён).

```
now < startISO                              → upcoming
startISO ≤ now < startISO + durationDays    → active
now ≥ startISO + durationDays               → finished
```

### Этап 0 — Создание (админ/куратор)
Экран «Создать → Челлендж»: название, **дата старта** (ГГГГ-ММ-ДД), **длительность**
(дней, задаёт организатор, **минимум 14**, по умолч. 21), цена (опц.), **команды**
(название + размер «чел.» + email капитана опц.). Ежедневные задачи засеваются
сервером. Челлендж появляется в разделе **«Открыт набор»**.

### Этап 1 — Набор (`upcoming`)
Карточка челленджа → отсчёт до старта, категории и баллы, таблица пересчёта, список
команд, правила. **«Подать заявку»**: никнейм ≤ 9 символов и не более одной
заглавной буквы, выбор команды **этого**
челленджа, согласие на отслеживание шагов + согласие с правилами, прикрепляется
анкета талантов. Капитан/админ: `на рассмотрении → принята / отклонена` (с причиной);
после отказа можно подать заново. Команды заполняются до `capacity`.

### Этап 2 — Старт (`active`)
Автоматически на дату старта открывается **ежедневный трекер**: день X/N, календарь,
3 задачи дня с автоматическим сохранением до закрытия дня, «Мои флаги», лидерборд команды со **сводкой
(накоплено + штрафы) и штрафами/🚩 по каждому участнику**. Баллы вживую идут в сумму
команды. Провалы → штрафы и 🚩; 3 🚩 в категории → 🏳️ вылет.
**Выйти нельзя** до конца — кроме белого флага 🏳️ от капитана. Прогресс дня хранится
на устройстве и синхронизируется на сервер.

### Этап 3 — Завершение (`finished`)
Баллы фиксируются. **Победитель — команда с наибольшей суммой.** Участники могут
покинуть команду.

## 8. Контракт API (что должен присылать сервер)

Все `/api/mobile/*`. Аутентификация — Clerk `Authorization: Bearer <token>`
(кроме публичного каталога). Мобильный парсинг: `src/data/community.ts`, `src/data/api.ts`.

### 8.1 `GET /api/mobile/challenges` — публичный каталог
```jsonc
{
  "challenges": [
    {
      "id": "chl_123",
      "title": "Divergents challenge — сентябрь",
      "startISO": "2026-09-01T09:00:00.000Z",  // дата/время старта
      "durationDays": 21,
      "categories": ["Чтение", "No Sugar", "Активность"], // string[] | string | null
      "rules": "…текст правил…",                 // из него парсится «N 🚩 — вылет»
      "price": 12000,                            // число или null
      "status": "open",                          // open | active | finished (fallback, если нет startISO)
      "teams": [
        {
          "id": "team_a",
          "name": "Команда А",
          "capacity": 30,                        // РАЗМЕР КОМАНДЫ (настраивается)
          "captain": "user_2ab…",                // Clerk userId капитана или null
          "captainName": "Акназар",              // отображаемое имя или null
          "advisors": ["Данияр", "Аружан"],     // имена 2 советников (опционально)
          "_count": { "applications": 12 }        // принятых участников
        }
      ],
      "_count": { "applications": 27 }            // всего заявок по челленджу
    }
  ]
}
```
> Фаза (`upcoming/active/finished`) вычисляется на клиенте по `startISO` +
> `durationDays`; `status` используется как запасной вариант, если `startISO` нет.

### 8.2 `GET /api/mobile/challenges/active` — активный челлендж пользователя
Возвращает конфиг ежедневных задач (по которому клиент считает баллы) + **полный
лидерборд команды**. При отсутствии активного — `{ "challenge": null, "members": [] }`.

```jsonc
{
  "challenge": {
    "id": "chl_123",
    "title": "Divergents challenge — сентябрь",
    "teamName": "Команда А",
    "totalDays": 21,
    "currentDay": 7,               // текущий день челленджа
    "members": 30,                 // размер команды (можно опустить — доберётся из members[])
    "startedLabel": "с 1 сентября",
    "teamRank": 2,
    "teamCount": 30,
    "trainer": "",
    "price": "",
    "flags": { "R": 1, "NS": 0, "A": 0 },   // 🚩 ТЕКУЩЕГО пользователя по категориям
    "eliminated": false,                    // выбыл ли пользователь (3 🚩 → true)
    "tasks": [
      { "id": "reading", "kind": "metric", "title": "20 страниц книги",
        "icon": "book.fill", "unit": "стр.", "min": 20,
        "current": 0, "basePts": 20, "unitSize": 1, "ptsPerUnit": 1 },
      { "id": "sugar", "kind": "binary", "title": "День без сахара",
        "icon": "cube.fill", "done": false, "basePts": 0 },
      { "id": "steps", "kind": "metric", "title": "10 000 шагов",
        "icon": "figure.walk", "unit": "шагов", "min": 10000,
        "current": 0, "basePts": 25, "unitSize": 400, "ptsPerUnit": 1 }
    ]
  },
  "members": [
    {
      "id": "user_2ab…",
      "name": "Акназар",
      "weekBase": 260,        // НАКОПЛЕНО за прошлые дни (после штрафов, floored 0), БЕЗ сегодня
      "day": 7,
      "isMe": true,           // ровно один участник с isMe:true — это пользователь
      "flags": { "R": 1, "NS": 0, "A": 0 },
      "penalty": -400,        // всего штрафных баллов (отрицательное; уже учтено в weekBase)
      "eliminated": false
    }
  ]
}
```

**Разделение ответственности (важно):**
- `tasks[].current` — сегодняшние значения пользователя (клиент их правит и шлёт в
  `…/progress`). Клиент из `tasks` считает `баллы_сегодня`.
- `members[].weekBase` — **сумма чистых баллов за все ПРОШЛЫЕ дни** (после −100/−300,
  floored 0), **без сегодняшнего дня** (иначе двойной счёт: сегодня клиент добавит сам).
- Живые баллы пользователя в лидерборде = `weekBase + баллы_сегодня` (если не выбыл).
- `eliminated: true` → баллы участника заморожены, клиент их не увеличивает.
- **Видимость для всех:** приложение показывает лидерборд по КАЖДОМУ участнику
  (баллы + 🚩 `flags` + `penalty`) и сводку команды (накоплено + суммарные штрафы) —
  поэтому `flags`/`penalty` нужно присылать по всем `members`, а не только для `isMe`.
- Иконки задач — имена в SF-стиле (`src/components/SFIcon.tsx`); неизвестные
  деградируют до нейтрального глифа.

### 8.3 `POST /api/mobile/challenges` — создать (админ)
```jsonc
// body
{
  "title": "Divergents challenge — сентябрь",
  "startISO": "2026-09-01T09:00:00.000Z",
  "durationDays": 21,                  // задаёт организатор, минимум 14
  "price": "12 000 ₸",                 // строка или null
  "teams": [
    { "name": "Команда А", "capacity": 30, "captainEmail": "cap@x.kz" }, // capacity — любой размер
    { "name": "Команда Б", "capacity": 20 }
  ]
}
```
Сервер засевает ежедневные задачи (см. §3) сам. Ответ: `{ "id": "chl_123" }`.
Клиент не отправит `durationDays < 14`; сервер должен продублировать эту проверку.

### 8.4 `POST /api/mobile/challenges/:id/apply` — подать заявку
```jsonc
{ "teamId": "team_a", "profile": { /* анкета Talentslab, опционально */ } }
```
Ответ: 2xx = принято на рассмотрение (`pending`).

### 8.5 `GET /api/mobile/challenges/:id/applications` — заявки (капитан/админ)
Капитан видит только свою команду, админ — все.
```jsonc
{
  "canManage": true,   // true → админ (перенос в команду, назначение капитана)
  "applications": [
    {
      "id": "app_1",
      "applicantUserId": "user_9…",
      "userEmail": "a@x.kz",
      "userName": "Акназар",
      "status": "pending",         // pending | approved | rejected
      "feedback": "",
      "coefficient": 1,
      "teamId": "team_a",
      "teamName": "Команда А",
      "date": "2026-08-20",
      "profile": { /* анкета Talentslab или null */ }
    }
  ]
}
```

### 8.6 `PATCH /api/mobile/challenges/:id/applications` — решение по заявке
```jsonc
{ "applicantUserId": "user_9…", "status": "approved", "feedback": "", "teamId": "team_b" }
// teamId — только админ (перенос в другую команду); капитан шлёт status + feedback
```

### 8.7 `PATCH /api/mobile/challenges/:id/teams/:teamId` — капитан команды (админ)
```jsonc
{ "captain": "user_9…" }   // null → снять капитана
```

### 8.8 `GET /api/mobile/me/challenge-applications` — мои заявки
```jsonc
{
  "applications": [
    { "challengeId": "chl_123", "title": "…", "teamName": "Команда А",
      "status": "pending", "feedback": "", "date": "2026-08-20" }
  ]
}
```

### 8.9 `POST /api/mobile/challenges/:id/progress` — синхронизация задачи дня
```jsonc
{ "taskId": "steps", "value": 12000 }   // metric
{ "taskId": "sugar", "done": true }     // binary
```
Best-effort: клиент оптимистичен; сервер применяет значение, пересчитывает
баллы/штрафы/флаги дня.

### 8.10 Автоматическое закрытие дня (сервер)
Отдельный `POST .../report` не используется. Серверный cron в 23:01 Asia/Almaty
идемпотентно фиксирует значения задач, начисляет баллы/штрафы/🚩 и увеличивает
`currentDay`. Это должно работать без запущенного приложения. После дедлайна
`POST .../progress` не должен изменять уже закрытый день.
