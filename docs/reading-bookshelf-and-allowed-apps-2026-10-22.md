# Reading: постоянная книжная полка и разрешённые читалки

Статус: локальная реализация, **не опубликовано**. Номер сборки не изменён.
Продолжает `reading-multi-book-2026-10-21.md`; описанный там временный выбор
из истории заменён постоянной полкой. Для полки теперь нужна миграция БД.

## Поведение

- В «Моя книжная полка» можно заранее добавить несколько книг. Книги с нулём
  страниц не пропадают и не создают фиктивные результаты чтения.
- Добавление использует отдельный черновик и не заменяет выбранную книгу.
  Выбор книги для следующего подхода — отдельное действие на её строке.
- Одна книга закреплена за одним подходом. Новую книгу можно добавить и во
  время чтения, но выбрать её можно только после сохранения текущего подхода.
- Полка показывает накопленные страницы, время и следующую страницу каждой
  книги; «Сегодня» — только подтверждённые сервером результаты за день.
- Все подходы по разным книгам складываются в общую цель 60 минут. Пауза
  останавливает время; явное сохранение страниц завершает отдельный подход.
- Повторное добавление после потери ответа использует тот же operationId:
  дубль не создаётся. Ошибка не выдаётся за успешное сохранение.
- Возврат на экран и обновление жестом перечитывают полку, даже если на
  другом устройстве только добавили книгу, не записывая новый подход.

## Исключения Screen Time

Владелец согласовал ручной выбор читалок, понимая, что iOS не позволяет
надёжно отличить выбранную читалку от выбранной соцсети.

- В строгом режиме добавлен блок «Приложения для чтения» и системный
  `FamilyActivityPicker`. Сохраняются только отдельные приложения, максимум
  50; категории и сайты в исключениях отклоняются.
- Разрешение Screen Time выдаётся пользователем. После выдачи доступа UI
  перечитывает настройки. Пустой сохранённый список возвращает строгий режим.
- `.all(except: tokens)` сохраняет ограничения остальных приложений. Само
  управляющее приложение исключает iOS. Ограничения веб-категорий сохраняются.
- Выбор относится к аккаунту на конкретном iPhone. Непрозрачные токены остаются
  в защищённом App Group и не передаются JS, API или серверной диагностике.
  Общий `exportedSession` очищает также локальную выгрузку QA.
- При старте список копируется в журнал подхода. Пауза и возобновление
  используют этот же список; изменять его до сохранения подхода нельзя.
- Запоздавший picker после смены аккаунта (включая A → B → A), начала подхода,
  изменения настроек или замеченного отзыва разрешения не перезаписывает их.
- После замеченного отзыва разрешения нужен повторный выбор. Неопределённый
  статус на холодном старте не считается отзывом.

Документация Apple:
[applicationCategories](https://developer.apple.com/documentation/managedsettings/shieldsettings/applicationcategories-swift.property),
[FamilyActivitySelection](https://developer.apple.com/documentation/familycontrols/familyactivityselection).

## Проверки и границы

Mobile App Design Standards применён к самостоятельным компонентам, зонам
нажатия, переносам текста, состояниям загрузки/ошибок и VoiceOver.

- Серверный TypeScript проходит. Все серверные тесты: 224 PASS, 2 SKIP,
  0 FAIL; все 47 Reading-тестов, включая изолированный PostgreSQL, выполнены.
- Мобильный `npm run typecheck` — PASS; полный Jest — **908/908** тестов,
  **109/109** наборов PASS. Storybook manifest сгенерирован, `git diff --check`
  проходит в обеих рабочих копиях.
- Nullable-миграция применена дважды на тестовой БД; старый Prisma client
  сохранил возможность чтения. Проверены права/владение на уровне команд,
  приватность, повторные операции, rollback при сбое квитанции и неизменность
  активного подхода при добавлении книги.
- Реальные тела Swift проверены тестами; Store и Expo bridge прошли
  `xcrun swiftc -typecheck -target arm64-apple-ios16.2` с iPhoneOS SDK и
  установленными Expo/React headers. Store + QA также проходят typecheck;
  нативный focused-набор — 53/53 PASS.
- Полный Xcode archive, установка и новый физический сценарий iPhone
  в этой задаче не выполнялись. Работа конкретных онлайн-читалок и их
  встроенных веб-экранов пока не подтверждена на устройстве.
- Production, реальные участники/флаги/результаты не изменялись;
  коммиты, push и TestFlight не выполнялись.
