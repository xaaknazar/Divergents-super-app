# Достижения

Коллекция содержит 50 наград в 7 направлениях. Каталог и условия находятся в
`src/data/achievementCatalog.ts`, проверяемые правила — в
`src/data/achievementProgress.ts`. `AchievementProvider` один на авторизованное
дерево приложения: награды обновляются без посещения профиля.

## Источники прогресса

| Направление | Что засчитывается | Что не засчитывается |
| --- | --- | --- |
| Уроки | Сервер подтвердил завершение урока; курс достиг 100% | Оптимистическая отметка, mock-курс, ошибка запроса |
| Материалы | Система успешно открыла ссылку на уникальное вложение живого курса | Повторные открытия, ошибка открытия; это не подтверждение прочтения |
| Книги | Сохранённый статус «Читаю» / «Прочитал», опубликованная рецензия | Простой просмотр карточки, обычный комментарий, повторное добавление той же книги |
| Челленджи | Одобренное участие, ненулевой сохранённый отчёт за день, итог без выхода/дисквалификации | Календарь активного челленджа у зрителя, ожидающая заявка, отправка нуля, неподтверждённая отметка |
| События | Успешно созданная встреча/поездка/спорт; одобренная заявка | Заявка на рассмотрении, факт физического посещения (его приложение не проверяет) |
| Карта | Избранное, успешно отправленное место, опубликованный отзыв | Повторное сохранение той же точки, неотправленный локальный отзыв, физическое посещение |
| Тренировки | Создание личной программы, выполнение дневной нормы, все дни программы, сохранённая активность от 5 минут, достигнутая личная цель | Будущие дни, неполная дневная норма, повторные отметки в один день, слишком короткая активность |

Серия личных программ — максимальное число подряд выполненных календарных дней
по локальной дате телефона, как в существующем дневнике тренировок. Достаточно
выполнить норму одной программы в день. Несколько программ в тот же день не
увеличивают серию; переход между программами не прерывает её. Дни отчётов
челленджа считаются отдельно, по дате Алматы; эта метрика не обещает непрерывную
серию и не равна количеству полностью выполненных дневных заданий.

## Начисление и хранение

- Уникальный объект учитывается один раз, по ID. Число загрузок и повторных
  запросов не влияет на прогресс. Заработанные награды не отзываются при удалении
  локальной тренировки или временной недоступности сервера.
- Сохраняется время первого обнаружения награды, а не выдуманная историческая
  дата её получения. Интерфейс подписывает его «В коллекции с …».
- Первое восстановление данных происходит без потока уведомлений. Новые
  действия и изменения последующих серверных снимков показывают общий баннер.
- Незавершённое чтение локальной коллекции буферизует события; ошибка чтения
  не разрешает перезаписать старый файл. Повтор — кнопкой «Повторить загрузку»
  или обновлением экрана.
- Запись привязана к аккаунту. Поздние ответы старой сессии и ответы с JWT другого
  пользователя отбрасываются. Из JWT читается только `sub` для сопоставления;
  проверка авторизации по-прежнему выполняется сервером.
- Хранилище **локальное**, очищается при выходе и удалении аккаунта в соответствии
  с действующей политикой приложения. Полного переноса наград между устройствами
  нет. Нужен отдельный серверный журнал достижений для такой гарантии.
- Уже существующий серверный прогресс курсов, уроков, книг, одобрений и итогов
  челленджей восстанавливается. Детали пройденных курсов запрашиваются с
  ограничением параллелизма, без оценки числа уроков по округлённому проценту.
  Старые рецензии уточняются при открытии книги. Материалы, отчёты челленджа,
  создание событий и отправка/отзывы мест учитываются с этого обновления,
  потому что доступного общего исторического API для них нет.

## Дизайн и доступность

- Компактный итог коллекции и ближайшая цель; отдельные фильтры по статусу
  и раскрываемый список направлений без скрытых за горизонтальной прокруткой пунктов.
- Карточка показывает условие и прогресс; полные условия и переход в раздел
  раскрываются на месте, без модального окна.
- Сетка адаптируется к ширине и размеру текста, при крупном шрифте — одна колонка.
  Кнопки имеют область нажатия не меньше 48 точек, выбранное/раскрытое состояние
  передаётся средствам доступности. Цвета используют светлые/тёмные токены темы.
- В профиле у медалей есть названия. Баннер награды не закрывается автоматически
  при включённом экранном дикторе.
- Пока сохранённые данные не прочитаны, экран не показывает ложную пустую коллекцию.
  Ошибка загрузки имеет явную кнопку повтора. Ограничения локального хранения видны.

## Проверки

- Чистые правила: дедупликация, сохранение наград, 30 дней, пропуски,
  границы месяца/года, високосный день, DST, будущее, некорректные значения.
- Интеграция с API: только успешные подтверждённые действия, ожидающие заявки,
  повторные чтения и смена аккаунта до/после начала запроса.
- Провайдер: немедленное обновление, гидратация, ошибка чтения, выход из аккаунта,
  тихое восстановление и уведомление о новой одобренной заявке.
- Экран: фильтры, условия, переходы в разделы, светлая/тёмная тема,
  крупный текст, узкая/широкая сетка, пустые состояния и повтор загрузки.
- Нативный iOS Simulator: изолированный предпросмотр настоящего компонента
  на тестовых данных, светлая/тёмная тема, выбор направления и раскрытие условий.
  Это не проверка реальных серверных начислений или релизной сборки.

Перед выпуском нужна ручная проверка VoiceOver/TalkBack и размещения баннера
на физических iOS/Android-устройствах. Нативный Android-предпросмотр не выполнялся.
