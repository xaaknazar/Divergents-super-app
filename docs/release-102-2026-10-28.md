## Удаление аккаунта

В production Clerk настройка `user_settings.actions.delete_self` была `false`,
тогда как приложение вызывало `user.delete()` из кнопки удаления. Это реальный
запрет сервиса авторизации, а не ошибка подключения к VPS.

После отдельного подтверждения владельца в Clerk → Configure → User &
authentication → User model включено **Allow users to delete their account**,
настройка сохранена и выполнено **Apply to existing users → Update**.

Проверка 2026-10-28 05:55:53 UTC:

- публичная конфигурация: `delete_self=true`;
- read-only проверка всех **2586** существующих пользователей: у всех
  `delete_self_enabled=true`, выключенных и неизвестных значений нет;
- `reverification=false` осталось прежним; настройки входа и MFA не менялись;
- **0 аккаунтов удалено**. Полный разрушительный сценарий на живом аккаунте
  не выполнялся. Тесты порядка очистки и сохранения данных при отказе проходят.

Исправление настройки действует и для 101 после обновления состояния сервиса
авторизации. Нового серверного обработчика удаления нет: сохранён существующий
контракт удаления профиля Clerk и локальных данных устройства. Удаление записей
LMS/Talentslab в эту правку не добавлялось и не проверялось.
