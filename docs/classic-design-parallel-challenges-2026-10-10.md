## Несколько челленджей

- `fetchActiveChallenges` получает `GET /api/mobile/challenges/active?all=1`.
  Пустой успешный список отличается от ошибки/старого формата/повреждённого
  ответа. Дубликаты ID не считаются достоверным снимком.
- `ChallengeContext` хранит снимки всех активных подтверждённых участий.
  `useChallenge(challengeId)` отдаёт только нужный снимок. Неизвестный ID не
  подменяется первым челленджем и не разрешает запись.
- Общая долговечная очередь остаётся одной; операции и ошибки разделены по
  challengeId. Сохраняются operationId, expectedVersion, конкретный день,
  подтверждение квитанцией, повторы и восстановление после перезапуска.
- Поздние ответы, смена аккаунта и callbacks вчерашнего дня не могут
  перезаписать актуальное состояние или отправить отметку в другой день.
- `CommunityFeed` и `CommunityChallenges` показывают собственные активные
  участия, другие идущие челленджи и новый набор. Чужая карточка не даёт
  доступа к трекеру. Ошибка загрузки участия не выдаётся за отказ в доступе.
- Экраны отметок, команды, общего рейтинга и истории дней используют ID из
  маршрута. Экран отметок перемонтируется при смене челленджа/дня.
- `ChallengePicker` явно выбирает, в какой челлендж засчитать тренировку.
  Существующее правило «тренировка добавляется один раз» не изменялось.
- Достижения учитывают все активные участия, не только первое.

## Сервер

Изолированный release checkout: `/tmp/divergents-rankings-release.VtRe2m/lms`.
В `origin/main` сохранены коммиты `503b2b3` (новый API) и `57a9d45`
(capability для release gate). Старый singleton-ответ без `all=1` сохранён.
Участие проверяется на сервере для каждого challengeId; pending и чужие
челленджи не попадают в список редактируемых. Миграций и исправлений данных нет.
Сайт, рейтинги и актуальный расчёт штрафов не откатывались.

Git deployment `dpl_49sk6WqKGihNMmfvQcPM24VPmbQN` (коммит `57a9d45`)
получил Ready и домен `https://divergents-lms.kz`. Production release gate
успешен. После публикации в браузере подтверждены обе карточки: текущий
2 season и новый Teachers version. Прямую авторизованную API-проверку
браузер заблокировал; чужие токены и тестовые участия не создавались.
Ограниченная выборка 100 runtime-записей: 82 ответа 200, 3 ответа 401,
15 без конечного HTTP-статуса; записей уровня error/fatal нет. Это не
нагрузочный тест и не полный прогон на аккаунте с двумя активными участиями.

Перед мобильным релизом release gate требует `activeMemberships: true` вместе
с поддержкой v2-квитанций. Возврат только старого серверного API теперь
остановит выпуск новой мобильной сборки.
