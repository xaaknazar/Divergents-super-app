# Читательский челлендж — состояние реализации, 19 октября 2026

## Граница выпуска

Это код нового режима в основном React Native приложении, а не замена существующих R/NS/A челленджей.
Публикации в TestFlight/Google Play и миграции рабочей базы в рамках этой работы не было.
API скрыт серверным `READING_CHALLENGES_ENABLED`; создание — клиентским
`EXPO_PUBLIC_READING_CHALLENGES`; нативные разрешения подключаются только при
`READING_FOCUS_PILOT=true`. В обычную сборку нельзя незаметно включать неутверждённые entitlements.

## Правила после уточнения пользователя

- Обязательные 60 минут в сутки можно разделить на подходы. До часа — только пауза.
- Переход через 60 минут **не снимает** ограничения: начинается секундомер дополнительного чтения.
- После часа доступны пауза/завершение подхода. Можно снова почитать дополнительно.
- Пауза немедленно снимает ограничения локально, независимо от сервера; страницы за подход обязательны.
- В 00:00 Asia/Almaty нативный предел останавливает сеанс. Уже подтверждённые подходы учитываются
  без отдельного «завершить день», включая оставленный на паузе таймер.
- 15 минут после полуночи — доставка, не дополнительное время для вчерашнего дня.
- Неполученный отчёт/нарушенная целостность — проверка, не автоматический красный флаг.
  Страницы, которые человек не ввёл, не выдумываются.
- Подтверждённый час не отменяется из-за спорного дополнительного подхода. Сервер агрегирует
  проверенные сеансы; отклонённые/ожидающие проверки сохраняются в журнале отдельно.
- Три пропущенных дня суммарно прекращают участие. Рейтинг: выполненные дни, затем страницы;
  для команды — доля выполненных дней. Дополнительное время показывается отдельно, баллы не придуманы.

## Слои

- `src/data/reading.ts`: проверяемый контракт, авторизованный API, без mock-успехов записи.
- `src/state/useReadingChallenge.ts`: восстановление подтверждённого экрана, согласование нативного
  журнала с сервером, устойчивость к смене аккаунта/челленджа и нестабильной функции Clerk getToken.
- `src/state/readingOutbox.ts`: общая последовательная очередь для всех экранов, сохранение до
  отправки, неизменяемые operationId, повтор после потери ответа, запрет отправки чужого аккаунта.
- `src/components/Reading*`: самостоятельные визуальные компоненты, семантические props,
  стили внутри, внешнее размещение через Wrapper. Для каждого компонента есть Storybook.
- `modules/reading-focus`: локальный Expo-модуль, журнал без credentials, монотонные часы.
- `plugins/withReadingFocus.js`: opt-in monitor/widget на iOS и opt-in сервисы Android.
- `native-tests/reading-focus`: отдельное диагностическое приложение, без реальных аккаунтов/отметок.

## Сервер

Репозиторий: `/Users/xaknazar/divergents-kz-release.FBoVng`.
Маршрут `/api/mobile/reading-challenges`, отдельные Reading* таблицы.
Применять последовательно: `20261019_reading_challenges.sql`, `20261019_reading_overtime.sql`,
`20261019_reading_segment_review.sql`. Только после резервной копии и проверки rollout.
Никакого `db push` на production.

Транзакции блокируют аккаунт, затем челлендж. Частичный уникальный индекс дополнительно запрещает
две активные читательские сессии одного пользователя, даже в разных челленджах.
Администратор может проверить спорные подходы с обязательной причиной; решение и предыдущие
значения остаются в неизменяемой квитанции. Капитан не получает это право.
`hold`/`releaseHold` — административные API для известного инцидента; массовой UI-кнопки пока нет.

## Что НЕ считается подтверждённым

- Полный end-to-end основного приложения с реальным API на физическом телефоне.
- Незавершённый подход без введённых страниц остаётся ожидающим отчёта. Администратор может
  принять/отклонить спорный отчёт только после ввода страниц участником; принудительного
  закрытия такого подхода администратором пока нет.
- Переход через час в overtime с сохранением shield на физическом устройстве после последнего изменения;
  пользователь попросил перейти к основному интерфейсу, подтверждения этого нового теста нет.
- Перезагрузка телефона, принудительное завершение процесса, смена даты, 60-минутный/ночной прогон.
- Android: исходники есть, но на Mac нет SDK/JDK/adb и Android-устройство не подключено.
  Сборка и поведение Android не проверены; выпускать как готовое нельзя.
- Подключение Apple Family Controls **distribution** к основному App ID и обоим расширениям,
  затем проверка новых distribution-профилей. Разрешение аккаунту уже выдано (см. ниже),
  но development-подпись QA не доказывает готовность подписи выпуска.
- Google Play Accessibility/foreground-service декларации и review.

## Честные пределы защиты

Не обещаем полную блокировку телефона, запрет экстренных звонков, невозможность отозвать
разрешение/удалить приложение или доказательство фактического чтения. На iOS блокируются выбранные
токены приложений/категорий/сайтов. На Android — выбранные приложения через специальную возможность,
с явным объяснением и согласием пользователя, без чтения содержимого экрана.
Нативное время не зависит от часов JS; сервер ограничивает его доступным интервалом и границей дня.
Это не hardware attestation и не полная защита от модифицированного клиента.

Источники платформенных ограничений:
- https://developer.apple.com/documentation/familycontrols/requesting-the-family-controls-entitlement
- https://developer.apple.com/documentation/widgetkit/displaying-dynamic-dates
- https://developer.apple.com/videos/play/wwdc2022/110336/
- https://support.google.com/googleplay/android-developer/answer/10964491

Скилл Mobile App Design Standards использован для структуры экранов, touch targets, Dynamic Type,
светлой/тёмной темы и отключения декоративной анимации при Reduce Motion.

## Создание челленджа: исправления 19 октября 2026

- Вместо ручного ввода даты — системный календарь; начало с завтрашнего дня по Казахстану.
  На iOS календарь в прокручиваемой панели с подтверждением и отменой.
- Форма проверяет ограничения сервера, вместимость и повторяющихся капитанов. Ошибки показаны
  возле полей и рядом с основной кнопкой; первая ошибка озвучивается. Экран учитывает клавиатуру.
- До отправки запрос надёжно сохраняется на устройстве. После неопределённого ответа показываются
  точные сохранённые данные и явная повторная проверка с прежним operationId — без скрытой подмены
  новой формы старым запросом. Ошибка локального сохранения запрещает сетевую отправку.
- Экран успеха с общей анимацией открывается только после получения challengeId от сервера;
  переход ведёт в конкретный созданный челлендж.
- Первая ошибка загрузки каталога больше не скрывает раздел: доступна повторная загрузка.
- Применены Impeccable (operate/harden/polish) и UI/UX Pro Max: сохранены существующие цвета,
  визуальная иерархия, доступные подписи, состояния ожидания и ошибок. Новые компоненты имеют Storybook.
- Проверено после изменений: TypeScript; 82 suites / 566 tests, включая 16 новых тестов создания.
  В iOS Simulator визуально проверены форма, календарь, узкая форма с крупным текстом,
  тёмная сохранённая публикация и экран успеха. Это тестовые данные, не production E2E.
- В неподписанной проверочной сборке остаётся предупреждение expo-notifications о Keychain entitlement;
  оно не относится к созданию челленджа, но проверку уведомлений в этой сборке подтвердить нельзя.
- Эти изменения не опубликованы. Проверки реального API/физического телефона, Android и разрешений
  распространения из списка выше по-прежнему обязательны перед полноценным выпуском.

### Единое оформление создания

По замечанию пользователя отдельный крупный заголовок и вложенные карточки формы убраны.
Читательский челлендж и обычные мероприятия используют общие CreationFormLayout, CreationField,
CreationTypePicker и CreationTextInput: шапка «Создать / Отмена», компактные подписи, поля на
группированном фоне, закреплённая кнопка «Опубликовать». Панель действия занимает своё место
в раскладке и не перекрывает последние поля. У общих компонентов добавлены истории.
Механизм надёжной отправки, календарь и серверные контракты не изменены.
Проверки: TypeScript и 82 suites / 567 tests, включая сохранённые тесты создания мероприятий.
