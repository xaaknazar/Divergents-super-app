# Сообщение о занятом псевдониме

## Причина

Проверка на экране выбора имени обращалась только к Talentslab. Уникальный
индекс LMS мог отклонить сохранение (`409 nickname_taken`), но транспорт
синхронизации превращал этот ответ в `false`. Анкета показывала сообщение
об офлайн-сохранении вместо ошибки поля, а очередь повторяла конфликт.

## Изменения

- Предварительная проверка в обоих сервисах. Доступность подтверждается
  только двумя положительными ответами; недоступная сеть не означает «свободно».
- Авторизованный GET `/api/mobile/me/nickname?nickname=...` исключает собственный
  аккаунт из поиска, не раскрывает владельца и ничего не записывает.
- Экран выбора имени и анкета показывают: «Этот псевдоним уже занят. Выберите другой.»
- При окончательном конфликте серверного сохранения форма не закрывается и не
  сообщает об успехе. Черновик и другие ответы сохраняются.
- Конфликт помечается в очереди; фоновые попытки приостанавливаются до явного
  повторного сохранения. Новое имя отправляется вместе с ранее сохранёнными ответами.
- Ответы запоздалых проверок не должны окрашивать уже изменённое имя.
- Аккаунты не объединяются, чужие имена не освобождаются и не переносятся.

## Проверки

- `npm run typecheck` — успешно.
- `npm test -- --silent` — 49 наборов, 322 теста.
- Backend: 132 теста; TypeScript и lint изменённого маршрута — успешно.
- Проверены коллизия только в LMS, своё неизменённое имя, отказ сети,
  конфликт при окончательном сохранении, сохранность черновика и остановка повторов.

## Доставка

Изменения интерфейса находятся в исходниках мобильного приложения.
Новая мобильная сборка в рамках этой задачи не создавалась и не публиковалась.
Для установленного приложения потребуется обновление.
Два сервиса не составляют общую транзакцию: при временном отказе второй записи
синхронизация остаётся в очереди; успех подтверждается только после обеих записей.
