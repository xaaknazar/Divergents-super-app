выпускай». **Версия 1.0.0 (95) доступна во внутренней группе TestFlight

журнального flock. Обновлены проверки разрешения и устранены лишние
обновления карточки; логотип на карточке полностью белый.

Последняя проваленная трассировка:
`/tmp/divergents-reading-strict-qa/claude-pause-stuck-refreshed.json`.
Она относится к предыдущей установленной QA, а не принятому исправлению:

Причина смены процесса без системного crash-журнала не доказана.

Дополнение владельца после физической проверки: дизайн карточки одобрен;
на паузе нужна кнопка **«Возобновить»**. Подтверждено новое правило: страницы
вводятся при завершении подхода, не при каждой паузе. Новый кандидат содержит
soft-pause/resume для новых iOS-сеансов; старый протокол не переоткрывается.

## Точное воспроизведение со слов владельца

1. Запустить отдельный тест «15 минут» в Divergents Reading QA.
2. Заблокировать iPhone; карточка с таймером появляется.
3. Нажать «Пауза» на карточке: ограничения действительно снимаются,
   карточка исчезает.
4. Открыть QA: старый экран продолжает отсчёт.

Это уточнение заменяет первоначальное предположение об исчезновении только
после разблокировки. Старый обработчик явно завершал Live Activity при паузе;
старый QA держал running-снимок в UI. Не доказана неисправность ActivityKit.

## Исправления

- Пауза немедленно снимает защиту, сохраняет монотонное elapsed и переводит
  карточку в paused с неподвижным временем вместо её завершения.
- Внешняя пауза сразу учитывается на foreground приложения, даже если API
  занят/недоступен. Сохранённые target/elapsed имеют приоритет над часами UI.
- Карточка компактная: белый логотип, крупные цифры и одна кнопка;
  «Пауза» сменяется на «Возобновить». Дополнительное время не заменяется нулём.
- Монитор принадлежит конкретному сеансу. Поздний callback не закрывает
  paused-карточку и не может затронуть другой новый сеанс.
- Список карточек для отложенной очистки фиксируется заранее. Новый подход
  заменяет предыдущие карточки того же аккаунта только после успешного
  создания; неподтверждённые данные не удаляются.
- Частичный принятый отчёт сохраняет paused-карточку; принятый отчёт,
  выполнивший цель, завершает её. QA-сброс отдельно завершает карточку.
- Ручное восстановление отсутствующей running-карточки не перезапускает
  чтение, не включает защиту заново и не начисляет время.
- Выход из аккаунта отдельно убирает карточки через `endLiveActivities`,
  сохраняя нативное доказательство незагруженного времени. Это не обычная
  пауза. Наличие журнала не требуется для удаления оставшейся карточки.
- Снятие защиты при намеренной паузе и проверка журнала сериализованы:
  одновременный опрос не принимает снятую защиту за отзыв разрешения.
  При ошибке блокировки файла/чтения защита всё равно снимается.

## Критерий физической приёмки

«15 минут» → экран блокировки → «Пауза»: приложения доступны, карточка
остаётся с «На паузе», время замерло. Возврат в QA и повторная блокировка
не возобновляют ни время, ни ограничения. QA-сброс убирает карточку.
При достижении обязательной цели дополнительное время также замораживается
на паузе. Данные основного приложения не заменять.

При провале остановить выпуск. Не загружать старый IPA 94 вместо исправления.

### Новое возобновление — отдельная обязательная проверка

Сбросить прежний QA-тест (без `resumeVersion`) и начать свежий.
Экран блокировки: «Пауза» → «Возобновить» → «Пауза».
Проверить снова включённую защиту при возобновлении, продолжение отсчёта
без сброса и исключение времени ожидания. В приложении тот же сеанс,
на мягкой паузе нет формы страниц. До цели завершение запрещено.
Дополнительное время также продолжается; завершение после цели закрывает
сеанс и требует страницы. Два быстрых/устаревших нажатия не создают второй
сеанс и не воздействуют на более новую паузу.

### Границы сохранения и совместимость

- Новая нативная запись имеет `resumeVersion: 1`, накопленное активное время,
  неизменный монотонный deadline и отдельную generation для каждого перехода.
- Мягкая пауза не отправляет необратимый `stop`. Финальное закрытие сначала
  запечатывает локальный журнал и лишь затем отправляет накопленное время.
- Старые записи, прежние сборки и Android сохраняют старый сценарий:
  уже отправленный/очередной `stop` нельзя переоткрыть с другим elapsed.
- Серверное начисление всё ещё требует отчёта со страницами. Мягкая пауза
  сохраняет время **локально**, не является серверным checkpoint.
  В текущем API нет heartbeat/checkpoint и автоматической отправки страниц.
  После полуночи + 15 минут действует прежний режим проверки позднего отчёта.
  Этот клиентский релиз не заявляет решение автоматической серверной доставки
  при закрытом приложении; сервер/БД не изменялись.
- Пауза не переносит границу дня. Просроченный, отозванный или переживший
  перезагрузку незавершённый сеанс нельзя возобновить.
