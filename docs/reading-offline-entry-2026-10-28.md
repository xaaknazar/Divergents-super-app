# Reading: доступ к офлайн-таймеру из «Сообщества»

В сборке 101 таймер, детали челленджа и выбранная книга уже сохранялись на
телефоне. Но `useReadingCatalog` держал список карточек только в состоянии
компонента. После перезапуска приложения или повторного открытия раздела без
сети список был пуст: существующий офлайн-таймер нельзя было открыть из интерфейса.
Пользователь подтвердил, что сами вкладки доступны — вход в аккаунт не сломан.

## Исправление

- `readingCatalogCache` использует существующий механизм локального кэша чтения:
  отдельный ключ, привязка к аккаунту, одна сохранённая подборка. Список карточек
  не истекает через сутки. Настройки кэша обычных челленджей остаются прежними.
- `useReadingCatalog` одновременно восстанавливает карточки с диска и обновляет
  список через сервер. Зависший запрос или обновление токена не скрывают карточки.
  Явный отказ сервера удаляет устаревший список; пустой/выключенный каталог тоже
  заменяет прежние карточки. Запоздавший ответ другого аккаунта отбрасывается.
- «Главное» и «Челленджи» открывают сохранённую карточку через прежний маршрут
  `ReadingChallenge`. Карточка ничего не разрешает сама: участие, нативная защита,
  часы и очередь результатов проверяются существующим механизмом таймера.
- Полка книг восстанавливается до ожидания сети, а не после сетевой ошибки.
  Из неё можно выбрать книгу сразу. Загрузка ограничена 10 секундами вместе с
  получением токена; запоздавший ответ не заменяет новое состояние.
- При выходе из аккаунта список удаляется и ожидающие ответы инвалидируются.
  Незавершённый таймер и очередь результатов не очищаются.
- Подсказки различают сохранённые карточки и отсутствие первой загрузки.
  Для полки без сети больше не показывается неверный совет «обновить сервер».
  В Storybook добавлен тёмный вариант сохранённого списка при ошибке обновления.

## Проверки

TypeScript проходит. Полный прогон: 123 набора, 1070 тестов без ошибок.
Отдельно проверены перезапуск с сохранённым каталогом, отсутствие/зависание токена,
доступ через оба раздела сообщества при зависшей ленте, смена аккаунта, выход,
отказы доступа, пустой каталог, повреждённая копия и поздние ответы.
Сценарий каталог → настоящий хук таймера → офлайн-старт сохраняет действие в очередь.
Существующие проверки паузы, страниц, полуночи и последующей синхронизации проходят.

Физический iPhone в этом изменении не проверялся. Контрольный сценарий для него:
с интернетом открыть свой челлендж и полку → включить авиарежим → полностью закрыть
и открыть приложение → «Сообщество» → Reading → выбрать сохранённую книгу → старт,
пауза и страницы → вернуть сеть и убедиться, что результат отправлен один раз.

## Выпуск

Это клиентское исправление; сервер и БД менять не требуется. В опубликованную
сборку 101 оно не входит, новая сборка пока не выпущена. После обновления нужно
один раз открыть «Сообщество» и свой Reading challenge с интернетом, чтобы
сохранить вход и данные на этом устройстве. Первое вступление и добавление новых
книг по-прежнему требуют связи с сервером; офлайн доступны сохранённые данные.
