# iOS 105 — оформление покупки курса

Сборка 105 успешно собрана и загружена Apple для внутреннего TestFlight.
После загрузки владелец остановил дальнейшую публикацию; публичный релиз
на проверку не отправлялся. Реальные списания не включены.

30 октября в 14:21:57 Алматы владелец также потребовал выключить покупки
в приложении. На production установлено `APPLE_COURSE_PURCHASES_ENABLED=false`
и очищен `APPLE_IAP_SANDBOX_USER_IDS`. Это блокирует новую покупку и выдачу
доступа по Sandbox, включая восстановление и webhook. Ранее выданные доступы
не отозваны. Подробности: [отключение покупок](apple-purchases-disabled-2026-10-30.md).
Не восстанавливать прежнюю конфигурацию при следующем мобильном выпуске.

Исходник IPA: `8b92a134ced5dc4ec8a9abc0591b445891adce43`.
SHA-256 IPA: `5f3996207fe5d39c8f5c291fc636809b39f5640254efbf67e140dafee281f044`.
Подписи трёх targets и нативный модуль покупок проверены; Apple validate/upload
завершились успешно. Текущий статус обработки/доступности TestFlight после
просьбы остановиться отдельно не проверялся.

## Изменения

- Исправлен конкретный случай `6,99\u00a0$`: неразрывные пробелы Apple
  нормализуются перед отображением Gotham Rounded. Валюта и сумма Apple
  сохраняются; конвертации и подмены цены сайта нет.
- Цена показана один раз, отдельно от кнопки «Купить курс». На узком экране
  и при увеличенном шрифте строка цены перестраивается вертикально.
- Карточка доступа объясняет состав покупки; огромная дублирующая цена удалена.
- Восстановление убрано с экрана курса. В профиле добавлен раздел
  «Покупки курсов» → «Восстановить доступ», с объяснением про смену телефона.
  Явное восстановление сохранено для non-consumable покупок по правилу 3.1.1.
- Пока покупка подтверждается, повторная оплата недоступна. Сохранилась
  отдельная проверка ожидающей оплаты и выдача доступа после серверной проверки.
- Компоненты и состояния добавлены в Storybook; внутренние стили не пробрасываются.

## Проверки

- TypeScript — без ошибок.
- Jest: 129 наборов, 1103 теста успешно, 0 ошибок. Первый запуск без доступа
  к системному Swift-кэшу дал 5 ошибок окружения; полный повтор с доступом
  завершился с кодом 0. Проверены нормализация цены, запрет повторной покупки,
  восстановление из настроек, прежние нативные тесты чтения.
- На симуляторе iOS 26.5 проверен компонент с исходной проблемной ценой и
  настоящим Gotham Rounded. Покупки на устройстве в сборке 105 ещё не проверены.
- Владелец подтвердил покупку в 104. На сервере прочитана запись Sandbox
  курса «4 параметра руководителя» от 30 октября 08:40:33 UTC: не отозвана,
  доступ сохранён. Это тестовая покупка без реального списания.

## Реальная оплата

В App Store Connect первая версия 1.0 пока PREPARE_FOR_SUBMISSION; к старому
черновику привязана сборка 50. Русское и английское описание актуализированы,
ссылка поддержки проверена и сохранена. Скриншоты и данные входа
для App Review отсутствуют; App Privacy ещё не заполнена. У товаров ещё MISSING_METADATA.
Черновик не отправлялся. Первая покупка каждого типа должна отправляться
вместе с новой версией приложения.

Production App Store Server API 30 октября повторно ответил 401; тот же ключ
в Sandbox проходит проверку. Инженер Apple поясняет, что Production API
открывается после первого production-релиза. Это не повод менять рабочий ключ
или считать неподтверждённые платежи оплаченными.

До выпуска необходимы: проверяемый вход App Review, актуальные скриншоты и
метаданные приложения и 21 товара, анкета App Privacy по фактическим данным,
проверка боевого API после первого релиза. Sandbox-доступ ревьюера должен
быть разрешён отдельно; сейчас доступен только подтверждённому владельцу.
Настройки стран (только Казахстан) и согласованные цены не изменялись.
Данные покупок и серверные режимы этим UI-изменением не менялись.
