# Синхронизация анкеты: приложение, Talentslab и заявка

## Найденные разрывы

- `JoinChallengeScreen` прикладывал анкету только при `live === true`. Реальные локальные ответы после неудачной синхронизации не попадали в заявку.
- `useResume` повторял неудачную отправку только один раз при монтировании. Несколько экземпляров хука могли независимо отправлять анкету; не было привязанной к аккаунту очереди сохранённых версий.
- Скалярные поля из Talentslab заполняли только пустые локальные значения, поэтому старые непустые значения перекрывали новые изменения на сайте.
- API просмотра заявки превращал отсутствие записи, отсутствие серверного ключа и сетевую ошибку в одинаковый `null`. Мобильный экран называл всё это «анкета не найдена».

## Исправления

- Заявка включает заполненную анкету из приложения независимо от наличия записи в Talentslab, сохраняя доступные отчёты.
- `dvg.resumeOutbox.v1`: владелец, версия, сохранённые изменения и снимок. Запись в очередь предшествует отправке. Повтор — при запуске, возврате и раз в минуту, пока приложение активно. Черновик, который меняют после сохранения, не подменяет отправляемую версию.
- Повторы и одновременные сохранения сериализованы; подтверждение старой версии не удаляет новую; выход из аккаунта останавливает очередь и удаляет её данные.
- Новый LMS-маршрут `POST /api/mobile/me/profile-snapshot` обновляет только существующие заявки текущего авторизованного пользователя, сохраняя ранее приложенные отчёты. Идентификатор владельца и почта не берутся из тела запроса. Это восстанавливает старые пустые заявки при следующей синхронизации участника.
- Для создания/обновления записи используется существующий `POST /api/mobile/resume` Talentslab. В проверенном коде `MobileController::submitResume` уже создаёт `Candidate`, если по подтверждённой почте его нет; повторное сохранение обновляет найденную запись. Никаких секретных общих ключей в приложение не добавлено.
- При открытии заявки свежий профиль Talentslab имеет приоритет; при недоступности сохраняется снимок анкеты. Причина отсутствия данных передаётся отдельно.
- Серверные правки обновляют локальные поля, кроме активных правок и ожидающих синхронизации сохранений. При известном серверном состоянии отправляются только изменённые поля.
- HTTP 200 без `{ok:true}` больше не считается подтверждением сохранения анкеты.

## Проверки и выпуск

Добавлены тесты отправки первой анкеты, локального снимка заявки, двустороннего обновления полей, сетевого сбоя, очереди, конкурентных сохранений, перезапуска и выхода из аккаунта. Проверки используют вымышленные данные и подменённые сетевые ответы. Проверена типизация приложения и LMS.

Нужно сначала опубликовать LMS-маршрут и изменения выдачи заявок, затем выпустить новую мобильную сборку. До этого новая версия приложения будет сохранять очередь, но не сможет подтвердить обновление снимка через отсутствующий маршрут.

Боевые записи не редактировались; синхронизация конкретного пользователя со скриншота и состояние его анкеты в продакшене не проверялись. Старые данные, оставшиеся только на телефоне, нельзя восстановить с устройства администратора: участнику потребуется открыть обновлённое приложение. Автоповтор — пока приложение активно, не гарантированная фоновая задача ОС. Проверка новой регистрации на реальном Talentslab остаётся послерелизным приёмочным сценарием.
