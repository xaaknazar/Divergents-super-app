# Extreme reading — снятие красного флага за пять дней

Дата: 25 октября 2026. Реализовано локально; production и TestFlight не изменены.

## Правило

- Только постоянный (`continuous`) Reading challenge. Срочные командные Reading-челленджи и обычные R/NS/A-челленджи сохраняют прежние правила.
- Успешный день — сохранённый сервером дневной результат с `complete=true` и минимум 60 минутами чтения. Локально работающий таймер, неотправленные страницы и просто отсроченный штраф не дают успешного дня.
- При наличии красных флагов пять последовательных календарных успешных дней снимают один, самый ранний непогашенный флаг. Следующие пять снимают следующий: окна не пересекаются.
- Пропущенный день начинает серию заново. Невыполненный сегодняшний день сохраняет вчерашний прогресс до смены календарного дня. Отложенный прошлый день не даёт штраф, но не может соединить две серии; после доставки результата история пересчитывается.
- Флагов не бывает меньше нуля. Дни при нулевом балансе не создают списания на будущее.
- Пятый день учитывается сразу после сохранения результата, без ожидания полуночи. Дни — по прежней зоне Алматы; существующий 15-минутный запас доставки перед начислением флага сохранён.
- Правило применяется и к уже сохранённой истории участия, не только к будущим дням. Страницы, минуты, средний темп и оба рейтинга не меняются.

## Сервер — источник расчёта

Рабочая копия серверного репозитория: `/private/tmp/divergents-reading-reset-code.C7EDvl/source`, ветка `codex/reading-first-day-no-review`, база `5967b02f2a77e60b896eb19f3e98976a7c8c1d3c`.

- `lib/reading-continuous-policy.ts`: хронологический линейный расчёт. `flags` — оставшиеся флаги; `flagRecovery` содержит `requiredDays`, `progressDays`, `daysRemaining`, `earnedFlags`, `forgivenFlags`.
- История сохраняет исходный `missed`, минуты и страницы; `flagForgivenOn` указывает день снятия, `flagForgivenForDay` — погашенный день на записи успешной серии.
- `lib/reading-service.ts`: `flagRecoveryDays: 5` сообщает клиенту о поддержке нового правила. Профиль и рейтинг получают одну проекцию; дневник использует ту же функцию через `lib/reading-history.ts`.
- Изменять БД, запускать миграцию или отдельную задачу по списанию не нужно. Повторный запрос не списывает флаг повторно: всё выводится из истории, исходные записи не редактируются.

## Приложение

- Новые поля API необязательны: старый сервер и старый локальный кеш остаются читаемыми. Клиент не вычисляет скидку самостоятельно.
- `ReadingFlagRecovery` внутри `ReadingProgressSummary`: «Дней подряд: 3 из 5», объяснение правила, число снятых флагов. Поддержаны темы, масштаб текста и озвучивание прогресса.
- `ReadingDiary`: «Флаг снят», причина и персональный номер дня; исходный пропуск остаётся в истории.
- `ReadingRules` и `ReadingRankingContent`: описание нового правила появляется только при поддержке сервером.
- Storybook: отдельные варианты прогресса, последнего дня, нулевого баланса, тёмной темы и крупного текста; добавлены варианты правил, дневника и итоговой сводки.
- Предыдущие незакоммиченные изменения напоминаний о страницах и другие локальные изменения сохранены.

## Проверки

- Приложение: `npm run typecheck` без ошибок; полный Jest — **955/955**, 117 наборов; `storybook:generate`; `git diff --check`.
- Сервер: `tsc --noEmit` без ошибок; все `tests/*.test.ts` — **266 passed**, **3 skipped**, 0 failed. Пропущены проверки с отдельной PostgreSQL (оплаты, обычные отметки, Reading): тестовая БД не подключалась.
- Новый серверный набор: 12 тестов правила и 1 контрактный тест реальных функций detail/ranking/history с read-only заглушкой БД. Проверены 1024 комбинации десяти дней, границы 4/5/10 дней, пропуск, отсутствие отрицательного баланса/накопления скидок, личная дата вступления, поздние данные, полночь и запас доставки, повторные запросы и неизменность исходных данных.
- Сервер проверялся в отдельной чистой копии `/private/tmp/divergents-reading-flags-check.71HIlV`: исходные зависимости рабочего дерева оказались неполными. Установлены зависимости по lockfile без install-скриптов, затем сгенерирован Prisma-клиент; подключения к production не было.
- Новые мобильные состояния покрыты компонентными тестами и Storybook. Проверка этой карточки на физическом устройстве в данной задаче не выполнялась.

## Выпуск

1. Выпустить серверный код по существующей процедуре; безопасных миграций для этого изменения тоже не требуется.
2. Проверить одинаковый расчёт в detail и history, включая старые мобильные клиенты.
3. Выпустить мобильное обновление для прогресса и пояснений. Старые клиенты после получения свежего ответа уже увидят уменьшенное `flags`, но без новых пояснений.

Ничего не публиковалось и не коммитилось. Напоминания о страницах из предыдущей задачи отдельно требуют новой нативной сборки и проверки уведомлений на телефоне; исправления запуска из аудита стабильности не входят в это изменение.
